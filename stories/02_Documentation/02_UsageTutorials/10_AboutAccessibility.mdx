# 2.2.10. About Accessibility

Since bs.ch strives for compliance with [WCAG2.1 AA](https://access-for-all.ch/wcag-2-1/) and
[eCH-0059 Version 3.0](https://www.ech.ch/de/ech/ech-0059/3.0) certifications, accessibility is a very important
aspect of the DDS and all web applications related to bs.ch. Generally speaking, all components within Storybook should
adhere to a minimum accessibility standard to conform to these two guidelines.

To automatically test for accessibility violations, we introduced [Axe](https://github.com/dequelabs/axe-core) in
Storybook. The Storybook plugin that offers Axe adds a new tab to every component called "Accessibility" in which you
will see what it tested and what has passed.

In the rare case of a violation, please open up an issue on GitHub or inform the dev team directly.

## Using `aria-*` attributes and `sr-only`

Every component within Storybook offers an exhaustive set of `aria-*` attributes and elements for screen readers using
the `sr-only` ("Screen Reader Only") class. However, in case you want to build your own components and structure, adding
more labels and attributes may be necessary.

Since Tailwind is utility-based, you're entirely free if ou want to either use `sr-only` or `aria-*` attributes, while
the latter is to be preferred. There are cases, though, where `sr-only` can be of benefit, for example to add extra text:

```html
<a href="https://www.example.com" target="_blank">
  Go to example.com <span class="sr-only">(Opens in a new tab)</span>
</a>
```

## Contrasts

For people with typical vision, contrast issues may not be obvious at first glance. However, they can be a a great
hindrance for people with either colour vision deficiency or other visual impairments that do not require the use of a
screen reader.

To ensure enough contrast (at least 4.5:1 for WCAG2.1 AA), Storybook offers a [contrast checker](/story/3-tailwind-tools-contrast-checker--default).
This contrast checker shows which color combinations have enough contrast and can, therefore, be used together. Under "controls",
you can find two drop downs: The foreground colour and the background colour. Both offer all colours found in the Tailwind
config.

For example, let's say we want to use `blue-500` as the foreground colour and `green-600` as the background color. The
contrast checker shows us that the contrast is 1.46:1, which is below the required minimum of 4.5:1. Typically, we would
now make the foreground a darker shade of the same colour and the background a lighter shade. The contrast checker tells
us that `blue-800` as the foreground and `green-200` as the background work well, since they offer a contrast of 5.46:1,
well above the required minimum of 4.5:1.

In case you'd need to check arbitrary colours not found in the Tailwind config, we found the
[WebAIM contrast checker](https://webaim.org/resources/contrastchecker/) works well.

## Font sizes

As the general rule of thumb: If we stick to the standard typography classes, font sizes will always be sufficiently
large. If we want to introduce our own elements, different font sizes may be necessary. The `text-xs` class, for example,
is `12px` large, which is the smallest font size we offer, which is still legible.

Generally: The smaller a text is, the more contrast it needs to be legible. If we introduce a custom font size of, say,
`6px`, we need to ensure that the contrast has as high of a value as possible.

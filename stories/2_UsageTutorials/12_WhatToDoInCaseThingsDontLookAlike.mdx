# 3.13. What to do in case things in Storybook don't look like the Figma design

There are several different possible cases in which the design from Figma does not correspond to the components found in Storybook.

## 1. Slight colour differences

In case of slight colour differences, usually, the version with more contrast is deemed more accessible and, therefore, likely the option to go for.

However, close collaboration with the Design Team at ITBS is necessary to resolve these cases, so Storybook and Figma align.

<hr />

## 2. Size differences of certain elements (i.e. inner spacings, font sizes, border widths, drop shadow widths, etc.)

In case some size of some element changes, usually Figma is the single source of truth and Storybook should be adjusted.

Check other designs, though: If the element was changed for that particular use case, it is possible to override styling using Tailwind.

For exmample, imagine needing a primary button. Such a button can be implemented with this code:

```html
<button class="button">
  Click me!
</button>
```

If a larger font size is needed, it can be increased with Tailwinds font size classes:

```html
<button class="button text-7xl">
  Click me!
</button>
```

Please consult [2.3 How to use Tailwind](/docs/2-tutorials-3-how-to-use-tailwind--docs) and the [official Tailwind CSS documentation](https://v3.tailwindcss.com/docs) as well as the [Tailwind Config Viewer](/docs/4-tailwind-tools-config-viewer--docs) for all options you have.

<hr />

## 3. Missing or different spacings

Usually, single components do not offer outer spacings, i.e. margins. Their container does. So, for example, radio
buttons do not have outer spacings, whereas the fieldset has inner spacing that will position the radio buttons correctly.

Some components, especially in the forms category, do not offer spacings in between form elements. **This is on purpose, as to not take away from the flexibility the DDS offers**.

For example, a radio button list could be implemented in many different ways. They could either be standalone:

```html
<label for="hello" class="radio mb-20">
  <input type="radio" name="helloworldfoo" id="hello" value="hello" />
  Hello
</label>

<label for="world" class="radio mb-20">
  <input type="radio" name="helloworldfoo" id="world" value="world" />
  World
</label>

<label for="foo" class="radio mb-20">
  <input type="radio" name="helloworldfoo" id="foo" value="foo" />
  Foo
</label>
```

Or with an unordered list that arranges the radio buttons with flexbox:

```html
<ul class="flex flex-col gap-20">
    <li>
        <label for="hello" class="radio">
          <input type="radio" name="helloworldfoo" id="hello" value="hello" />
          Hello
        </label>
    </li>
    <li>
        <label for="world" class="radio">
          <input type="radio" name="helloworldfoo" id="world" value="world" />
          World
        </label>
    </li>
    <li>
        <label for="foo" class="radio">
          <input type="radio" name="helloworldfoo" id="foo" value="foo" />
          Foo
        </label>
    </li>
</ul>
```

Or within a CSS Grid:

```html
<div class="grid grid-cols-1 auto-rows-auto gap-20">
    <label for="hello" class="radio">
      <input type="radio" name="helloworldfoo" id="hello" value="hello" />
      Hello
    </label>
    <label for="world" class="radio">
      <input type="radio" name="helloworldfoo" id="world" value="world" />
      World
    </label>
    <label for="foo" class="radio">
      <input type="radio" name="helloworldfoo" id="foo" value="foo" />
      Foo
    </label>
</div>
```

Each of these cases offers a different approach to layouting while keeping the spacing between radio buttons at 20px, either via margin bottom (`mb-20`) or by using Flexbox's or Grid's `gap` utility.

Please consult [2.3 How to use Tailwind](/docs/2-tutorials-3-how-to-use-tailwind--docs) and the [official Tailwind CSS documentation](https://v3.tailwindcss.com/docs) as well as the [Tailwind Config Viewer](/docs/4-tailwind-tools-config-viewer--docs) for all options you have.

<hr />

## 4. Missing components

In some cases, components found in Figma do not exist in Storybook. Either, the component hasn't been implemented yet, or is unique to the design.

In both cases, please consult [3.8. How to use use Tailwind and Storybook to create new components](/docs/3-usage-tutorials-8-how-to-use-use-tailwind-and-storybook-to-create-new-components--docs) as well as [/docs/3-usage-tutorials-5-how-to-use-bs-ch-to-find-missing-components--docs](/docs/3-usage-tutorials-5-how-to-use-bs-ch-to-find-missing-components--docs).

# 2.3. How to use Tailwind

## What are CSS frameworks

CSS frameworks are collections of pre-written CSS (and often JavaScript) code that streamline the process of building
web interfaces by providing ready-to-use styles and components. These frameworks establish a consistent design system
with features like responsive grids, typography, buttons, forms, and navigation menus. They help developers avoid
repetitive tasks, speed up development, and ensure cross-browser compatibility.

### Why Use CSS Frameworks?
 * **Efficiency:** They reduce the need to write CSS from scratch.
 * **Consistency:** Design elements maintain uniformity across the application.
 * **Responsiveness:** Many frameworks include tools for creating mobile-friendly designs.
 * **Customization:** Developers can extend or override the default styles to match specific project requirements.

### Popular CSS Frameworks

#### Bootstrap

 * One of the most widely used CSS frameworks.
 * Provides a robust grid system, responsive design utilities, and a wide range of UI components like modals, carousels, and tooltips.
 * Includes a JavaScript library for interactive elements.

#### Tailwind CSS

 * A utility-first CSS framework that emphasizes custom designs without relying on pre-styled components.
 * Developers can apply pre-defined utility classes directly in HTML to style elements.
 * Highly customizable, with a focus on performance and flexibility.

#### Foundation by Zurb

 * Known for its mobile-first approach and accessibility.
 * Provides a responsive grid system, buttons, forms, and other reusable components.
 * Includes tools for email design and motion UI animations.

#### Bulma

 * A lightweight and modern framework based purely on Flexbox.
* Offers an intuitive class-based system for creating responsive layouts.
 * Minimal reliance on JavaScript, focusing purely on CSS.

#### Materialize

 * Based on Google’s Material Design principles.
 * Features sleek, modern UI components like cards, tabs, and toolbars.
 * Provides built-in responsive design utilities.

#### UIkit

 * A modular framework with a focus on small, lightweight components.
 * Includes tools for animations, grid layouts, and responsive typography.

### How CSS Frameworks Are Used
Developers typically include a CSS framework in their project via a CDN (Content Delivery Network), a package manager like npm, or by downloading it directly. Once integrated, they can use predefined classes and components to build a design structure, tweaking styles as needed.

For instance, using Bootstrap, creating a responsive button is as simple as:

```html
<button class="btn btn-primary">Click Me</button>
```

In contrast, with Tailwind CSS, you might write:

```html
<button class="bg-blue-500 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded">Click Me</button>
```

### Conclusion
CSS frameworks are invaluable for developers aiming to build professional and responsive web designs efficiently.
Whether you prioritize simplicity, customizability, or modern design principles, there is likely a CSS framework that
fits your needs.

## Atomic CSS and utility-first approach

**Atomic CSS** and the **utility-first approach** are modern methodologies in styling web applications that emphasize
small, reusable, and highly specific classes for styling individual elements. These methods break down CSS into
single-purpose, "atomic" classes, each responsible for a single styling property (e.g., text alignment, margin, color).
Instead of writing custom CSS rules for each component or element, developers apply combinations of utility classes
directly to their HTML.

### What is Atomic CSS?

Atomic CSS is a styling philosophy where CSS classes are designed to perform one specific task. These classes act as
"building blocks" for styling, and complex designs are created by combining multiple classes. For instance, a class
like `text-center` aligns text, while `mt-4` adds a top margin.

### What is the Utility-First Approach?

The utility-first approach, popularized by frameworks like **Tailwind CSS**, takes the Atomic CSS idea further by
focusing on providing a comprehensive set of pre-defined utility classes for virtually every common CSS property.
Instead of writing new CSS for each project, developers use these utility classes to build designs directly within
their HTML.

### Benefits of Atomic CSS and Utility-First Approach

1. **Efficiency**: Eliminates the need for writing extensive custom CSS by using pre-existing classes.
2. **Consistency**: Ensures consistent spacing, typography, and styling across the project by reusing the same classes.
3. **Scalability**: Simplifies scaling projects because there are fewer custom CSS rules to maintain.
4. **Reduced CSS Bloat**: By using only the classes required for the design, unused styles are avoided, often resulting in smaller CSS bundles.
5. **Improved Development Speed**: Styling directly in the markup shortens feedback loops during development.

### Example in Practice

Using the utility-first approach, styling a button would look like this:

```html
<button class="bg-blue-500 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded">
  Click Me
</button>
```

Here:
- `bg-blue-500` sets the background color.
- `hover:bg-blue-700` changes the background on hover.
- `text-white` sets the text color.
- `py-2` and `px-4` define padding.
- `rounded` adds border-radius.

This eliminates the need to write custom CSS like:

```css
.button {
  background-color: #4299e1;
  color: white;
  padding: 0.5rem 1rem;
  border-radius: 0.25rem;
}
```

### Popular Tools and Frameworks

1. **Tailwind CSS**
   - The most popular utility-first CSS framework.
   - Offers a comprehensive range of classes for responsive design, layout, typography, and more.
   - Highly customizable via a configuration file.

2. **Tachyons**
   - Lightweight Atomic CSS library with utility classes for common styling needs.
   - Minimal setup with concise class names.

3. **ACSS (Atomic CSS)**
   - A pioneer in Atomic CSS, offering single-purpose utility classes.

### Comparison to Traditional CSS

| **Aspect**             | **Traditional CSS**          | **Utility-First / Atomic CSS**        |
|-------------------------|------------------------------|---------------------------------------|
| Styling Location        | Separate CSS files          | Directly in HTML                     |
| Granularity             | Component or element level  | Property or utility level            |
| Customization           | Custom styles per project   | Predefined utilities, customizable   |
| Learning Curve          | Moderate for large projects | Steeper initially, faster later      |

### Conclusion

Atomic CSS and the utility-first approach prioritize simplicity, reusability, and efficiency in web development. By
breaking styles into small, focused classes, they enable rapid development while maintaining design consistency. This
methodology is especially suited for projects with dynamic needs or teams looking to improve maintainability and
scalability in their CSS workflows.

## On-demand approach

Tailwind CSS uses an **on-demand CSS generation approach**, meaning it only generates the utility classes that are actually used in your project. Instead of providing a fully loaded stylesheet with every possible utility class, Tailwind dynamically generates the specific styles you need based on the classes referenced in your HTML, JavaScript, or other templating files. This approach ensures a minimal and optimized CSS bundle tailored to your project.

In the DDS, we use the following list of pattern to match for files that may include Tailwind classes:

```
"[YOUR PROJECT ROOT]/{components,pages,layouts,helpers,stories,dist,src}/**/*.{html,js,ts,jsx,tsx,vue,astro,svelte,mdx}"
```

While this covers most popular frameworks and architectures, some options may be missing. In that case, please reach out
to the devs via GitHub.

### How the On-Demand Approach Works

Tailwind relies on tools like **PostCSS** and a build process to scan your source code files for utility class usage. During the build, it identifies and compiles only the necessary CSS rules for those classes. Unused utilities are excluded from the final CSS output, keeping your stylesheets lean and efficient.

For example:
- If your project uses `bg-blue-500`, `text-white`, and `rounded`, Tailwind will only include the corresponding CSS rules for these classes.
- If you add or remove utility classes from your templates, the CSS bundle updates automatically in subsequent builds.

This process is often facilitated by tools like **PurgeCSS**, integrated directly into Tailwind's workflow.

### Benefits of the On-Demand Approach

1. **Smaller CSS Files**
   Since only the required utility classes are included, the final CSS file is lightweight, improving load times and performance.

2. **Optimized Performance**
   Reduced CSS bloat leads to faster rendering and better performance, especially for large projects or mobile-first designs.

3. **Dynamic Updates**
   Tailwind automatically adjusts the generated CSS as you modify your HTML or templates, ensuring that the stylesheet remains up-to-date.

4. **Scalability**
   This approach works well for projects of any size, as the generated CSS only grows with the complexity of your design.

5. **No Manual Cleanup**
   Unlike traditional CSS approaches where unused styles may accumulate over time, Tailwind ensures that only the necessary styles are included, simplifying maintenance.

### Example in Practice

Suppose you use the following HTML in your project:

```html
<div class="bg-blue-500 text-white p-4 rounded">
  Hello, Tailwind!
</div>
```

Tailwind's build process will scan your files, identify the referenced classes, and generate only the relevant CSS:

```css
.bg-blue-500 {
  background-color: #3b82f6;
}
.text-white {
  color: #ffffff;
}
.p-4 {
  padding: 1rem;
}
.rounded {
  border-radius: 0.25rem;
}
```

If you later remove or add classes in your templates, the CSS file will adjust accordingly during the next build.

### Comparison to Traditional CSS Frameworks

| **Aspect**             | **Traditional Frameworks**    | **Tailwind's On-Demand Approach**    |
|-------------------------|-------------------------------|--------------------------------------|
| CSS Size               | Large, includes all utilities | Small, includes only used utilities |
| Unused Styles          | Potential for unused styles   | Automatically excluded              |
| Development Workflow   | Pre-defined stylesheets       | Dynamic CSS generation              |
| Performance            | May require additional cleanup| Optimized for speed and size        |

### Conclusion

Tailwind's on-demand approach offers a powerful solution to the challenges of CSS bloat and inefficiency. By generating
only the necessary utility classes for a project, it ensures optimal performance, smaller file sizes, and a streamlined
development process. This approach is especially beneficial for modern, dynamic web applications where designs and
templates frequently evolve.

## Using Tailwind's utility classes

Tailwind CSS is a utility-first framework, meaning it provides a comprehensive set of small, single-purpose classes that
can be applied directly in your HTML to style elements. Instead of writing custom CSS or relying on predefined components,
you combine Tailwind's utility classes to create custom designs on the fly.

### How to Use Utility Classes

In Tailwind, each utility class is designed to apply a specific CSS property to an element. By combining these classes,
you can control almost every aspect of the design without writing a single line of custom CSS.

For example, to create a simple button, you could write:

```html
<button class="bg-blue-500 text-white py-2 px-4 rounded">
  Click Me
</button>
```

Here’s what each class does:
- `bg-blue-500`: Sets the background color to a specific shade of blue.
- `text-white`: Sets the text color to white.
- `py-2`: Adds vertical padding of 0.5rem.
- `px-4`: Adds horizontal padding of 1rem.
- `rounded`: Applies a small border-radius for rounded corners.

### Common Utility Classes

Tailwind provides a wide variety of utility classes to manage different design properties. Here are a few of the most
commonly used categories:

#### Layout
- `block`: Makes an element a block-level element.
- `inline`: Makes an element inline.
- `flex`: Enables a flexbox layout.
- `grid`: Enables a grid layout.

#### Spacing
- `m-4`: Applies a margin of 1rem on all sides.
- `mt-2`: Applies a margin-top of 0.5rem.
- `p-4`: Applies padding of 1rem on all sides.
- `py-2`: Adds vertical padding of 0.5rem.

#### Typography
- `text-lg`: Sets the font size to large (1.125rem).
- `font-bold`: Makes the text bold.
- `text-center`: Aligns text to the center.
- `uppercase`: Transforms text to uppercase.

#### Colors
- `bg-gray-200`: Sets the background color to a light gray.
- `text-red-500`: Sets the text color to a medium shade of red.
- `border-blue-500`: Sets the border color to a shade of blue.

#### Borders and Shadows
- `border`: Adds a default border around the element.
- `border-2`: Sets the border width to 2px.
- `shadow-lg`: Applies a large box-shadow.
- `rounded-lg`: Adds larger rounded corners.

### Combining Utility Classes

Tailwind's power lies in combining its utility classes to create custom designs without having to write custom CSS. For
example, to create a card component:

```html
<div class="bg-white border rounded-lg shadow-lg p-6 max-w-sm">
  <h2 class="text-2xl font-semibold text-gray-800">Card Title</h2>
  <p class="text-gray-600 mt-4">This is a simple card description.</p>
</div>
```

In this example:
- `bg-white`: White background.
- `border`: Default border.
- `rounded-lg`: Large border-radius for rounded corners.
- `shadow-lg`: Large box-shadow.
- `p-6`: Padding of 1.5rem.
- `max-w-sm`: Maximum width of the card.
- `text-2xl`: Large font size for the title.
- `font-semibold`: Semi-bold font weight.
- `text-gray-800`: Dark gray text color for the title.
- `text-gray-600`: Medium gray color for the description text.
- `mt-4`: Margin-top of 1rem for spacing between the title and the description.

### Conclusion

Using Tailwind's utility classes gives you fine-grained control over your design without the need for custom CSS. By
combining different utilities directly in your HTML, you can quickly build custom, responsive, and consistent layouts
while keeping your stylesheets minimal and easy to maintain.

## Pseudo-selectors (i.e. `:hover`, etc.)

Tailwind CSS provides a straightforward way to style elements based on their state using **pseudo-selectors** like
`:hover`, `:focus`, `:active`, and more. These pseudo-classes enable you to apply styles when an element is in a specific
state, such as when a user hovers over a button or focuses on an input field. Tailwind makes it easy to apply these
styles directly in your markup using the corresponding utility classes.

### What Are Pseudo-Selectors?

Pseudo-selectors in CSS are special keywords added to selectors that allow you to target elements in specific states or
conditions. Common pseudo-selectors include:
- `:hover`: When the user hovers over an element with a pointing device (like a mouse).
- `:focus`: When an element (such as an input) is focused, typically via keyboard navigation or clicking.
- `:active`: When an element is being activated, for example, when a button is being clicked.
- `:disabled`: When a form element is disabled.

In Tailwind, you can apply these pseudo-classes directly to utility classes by prefixing the utility with the state or
condition (e.g., `hover:bg-blue-500` for a background color change on hover).

### Using Pseudo-Selectors in Tailwind CSS

Tailwind makes it easy to apply styles for these states using simple class prefixes. Here's how you can use common
pseudo-selectors:

#### Example 1: Hover State

You can use `hover:` to apply styles when the user hovers over an element. For example, you might want to change the
background color of a button when it's hovered over.

```html
<button class="bg-blue-500 text-white py-2 px-4 rounded hover:bg-blue-700">
  Hover Over Me
</button>
```

In this example:
- `bg-blue-500` sets the default background color.
- `hover:bg-blue-700` changes the background color when the button is hovered.

#### Example 2: Focus State

The `focus:` pseudo-class applies styles when an element is focused. For instance, you can change the border color of
an input field when it is focused.

```html
<input class="border-2 border-gray-300 p-2 focus:border-blue-500" type="text" placeholder="Focus on me">
```

Here:
- `border-2` and `border-gray-300` set the default border style.
- `focus:border-blue-500` changes the border color to blue when the input is focused.

#### Example 3: Active State

The `active:` pseudo-class can be used to style an element when it is actively being clicked. For example, you might
want to change the background color of a button when it's clicked.

```html
<button class="bg-blue-500 text-white py-2 px-4 rounded active:bg-blue-800">
  Click Me
</button>
```

- `bg-blue-500` applies the default background color.
- `active:bg-blue-800` changes the background color when the button is actively clicked.

#### Example 4: Disabled State

To style disabled elements, you can use the `disabled:` prefix. This is useful for form elements like buttons and inputs
that should appear differently when disabled.

```html
<button class="bg-gray-300 text-gray-500 py-2 px-4 rounded disabled:opacity-50" disabled>
  Disabled Button
</button>
```

- `bg-gray-300` applies the background color.
- `disabled:opacity-50` reduces the opacity when the button is disabled.

### Combining Multiple States

You can also combine multiple pseudo-classes to create more complex interactions. For example, you might want a button to change color on hover and be slightly more transparent when disabled.

```html
<button class="bg-blue-500 text-white py-2 px-4 rounded hover:bg-blue-700 disabled:bg-gray-400 disabled:opacity-50">
  Hover and Disabled States
</button>
```

- `hover:bg-blue-700` changes the background color when hovered.
- `disabled:bg-gray-400` and `disabled:opacity-50` apply styles when the button is disabled.

### Conclusion

Tailwind's utility-first approach makes working with pseudo-selectors like `:hover`, `:focus`, `:active`, and `:disabled` extremely easy. By simply adding the relevant prefix to your utility classes, you can style elements based on their state without writing any custom CSS. This helps keep your markup clean and maintains the speed and flexibility of the utility-first workflow.

## Responsiveness

Tailwind CSS makes it easy to create responsive designs using its built-in responsive utilities. With Tailwind, you can
apply different styles at different screen sizes using simple, intuitive breakpoints. This flexibility allows you to build
designs that adapt seamlessly to a variety of screen sizes, from small mobile devices to large desktop monitors.

### How Tailwind's Responsiveness Works

Tailwind's responsive design is based on mobile-first principles. This means that you define styles for smaller screens
first, and then use Tailwind’s responsive modifiers to apply different styles as the viewport size increases. These
modifiers are added to the utility classes to control how elements behave at different breakpoints.

#### Breakpoints in Tailwind

Tailwind provides the following default breakpoints:
- `sm`: Small screens (640px and up)
- `md`: Medium screens (768px and up)
- `lg`: Large screens (1024px and up)
- `xl`: Extra large screens (1280px and up)
- `2xl`: 2x Extra large screens (1536px and up)

These breakpoints are used as prefixes to utility classes, enabling you to specify styles for specific screen sizes.

### Example of Using Responsiveness

You can use Tailwind’s responsive utilities to adjust the layout of elements for different screen sizes. For example,
to create a responsive grid layout, you could write:

```html
<div class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
  <div class="bg-blue-500 p-4">Item 1</div>
  <div class="bg-blue-500 p-4">Item 2</div>
  <div class="bg-blue-500 p-4">Item 3</div>
</div>
```

Here’s how it works:
- By default (`grid-cols-1`), the layout will have one column.
- For small screens (`sm:grid-cols-2`), it will switch to a two-column layout (at 640px and up).
- For large screens (`lg:grid-cols-3`), it will switch to a three-column layout (at 1024px and up).

#### Other Common Responsive Utilities

Tailwind provides many utility classes that are responsive by default. Here are a few examples:

- **Visibility**: You can control whether an element is visible at certain breakpoints:
  - `hidden`: Hides the element by default.
  - `sm:block`: Makes the element a block-level element starting from small screens.
  - `lg:hidden`: Hides the element on large screens and up.

- **Flexbox**: You can change flexbox layouts at different breakpoints:
  - `flex`: Applies a flexbox layout.
  - `sm:flex-row`: Makes the flex container arrange its items in a row starting from small screens.
  - `md:flex-col`: Changes the flex direction to column at medium screens (768px and up).

- **Text Size**: Tailwind allows you to adjust text sizes based on screen size:
  - `text-base`: Applies a default font size.
  - `sm:text-lg`: Increases the text size on small screens (640px and up).
  - `lg:text-xl`: Further increases the text size on large screens (1024px and up).

#### Example with Text Size and Padding

```html
<div class="text-sm sm:text-base lg:text-lg p-2 sm:p-4 lg:p-6">
  This text and padding will change based on screen size.
</div>
```

- On small screens (`sm:text-base`), the text size will be `base`.
- On large screens (`lg:text-lg`), the text size will increase to `lg`.
- The padding will also increase with screen size (`p-2`, `sm:p-4`, `lg:p-6`).

### Conclusion

Tailwind's responsive features allow you to design flexible and adaptive layouts with ease. By using its mobile-first approach and applying responsive utilities through simple class prefixes, you can create dynamic layouts that adjust to any screen size. This makes it easier to build modern, responsive websites that perform well across all devices.

## What to do in case Tailwind doesn't offer what we need

Tailwind CSS offers a powerful feature called **arbitrary value syntax**, which allows you to use custom values directly within Tailwind's utility classes. This syntax gives you the flexibility to apply non-standard values (such as specific colors, sizes, or spacing) without having to modify your `tailwind.config.js` file or create custom utility classes.

### What is Arbitrary Value Syntax?

Arbitrary value syntax allows you to specify a custom value in a Tailwind utility by enclosing it in square brackets. Instead of using predefined options like `bg-red-500` or `p-4`, you can insert any valid CSS value directly.

For example, you can use arbitrary values like this:

- **Custom Color**:
  `bg-[#ff6347]` will apply a background color of `#ff6347` (Tomato).

- **Custom Spacing**:
  `p-[10px]` will apply padding of `10px` to all sides.

- **Custom Font Size**:
  `text-[32px]` will set the text size to `32px`.

These custom values can be used in any Tailwind utility class that accepts a value.

### Examples of Using Arbitrary Values

1. **Custom Background Color**
   If you want to set a background color to a specific hex code:
   ```html
   <div class="bg-[#ff6347] p-4">Tomato Background</div>
   ```
   This will set the background color to `#ff6347`.

2. **Custom Padding**
   Instead of using the default spacing scale, you can specify an exact value:
   ```html
   <div class="p-[12px]">Custom Padding</div>
   ```
   This applies `12px` of padding to all sides.

3. **Custom Border Width**
   You can also apply custom border widths:
   ```html
   <div class="border-[5px] border-solid border-black">Custom Border</div>
   ```
   This sets the border width to `5px`.

4. **Custom Font Size**
   You can specify a custom font size in pixels, rem, or any valid unit:
   ```html
   <p class="text-[1.5rem]">Custom Font Size</p>
   ```
   This will set the font size to `1.5rem`.

### Benefits of Arbitrary Value Syntax

1. **Flexibility**: Tailwind’s default configuration works great for most use cases, but arbitrary values let you go beyond the built-in utility classes when you need custom values that aren’t part of the design system.

2. **No Need for Custom Utilities**: Instead of defining a new utility class in your `tailwind.config.js`, you can apply custom values directly within your markup.

3. **Reduced Configuration Overhead**: This syntax reduces the need to modify your configuration file for every new custom value you want to use, making your workflow faster and more efficient.

4. **Consistency**: Since you're still using Tailwind’s utility classes, you maintain the consistency and scalability of the utility-first approach without having to write custom CSS.

### Conclusion

The **arbitrary value syntax** in Tailwind CSS is a powerful and flexible feature that lets you apply custom values
directly in utility classes, without the need for additional configuration or custom CSS. Whether you need a specific
color, size, or spacing that’s outside Tailwind's default scale, arbitrary values offer a simple and efficient solution
to extend the flexibility of your design.

## Grouping often-used styles

One of the key advantages of Tailwind CSS is its utility-first approach, which encourages using a wide variety of utility
classes directly in your HTML. However, in some cases, it might be beneficial to group commonly used styles into reusable
custom classes. This can help reduce redundancy and improve maintainability, especially for repeated design patterns
across a project. Tailwind provides the `@apply` directive for this purpose.

### What is `@apply`?

`@apply` is a directive in Tailwind CSS that allows you to group utility classes into custom CSS classes. You can create
new classes that include multiple Tailwind utilities, making your code more readable and concise.

Instead of adding the same set of utility classes to every element manually, you can define a custom class with those
 utilities, then apply that custom class wherever needed. This is especially useful for patterns that appear frequently,
 such as buttons, cards, or form elements.

### Using `@apply` with Custom Classes

The `@apply` directive is used in your CSS files (or within your `@layer` directives, depending on your setup). You can
apply Tailwind's utility classes to custom class selectors to create reusable style groups.

#### Example 1: Creating a Reusable Button Class

Suppose you often use a button with specific styles like background color, padding, border radius, and text color.
Instead of applying these utilities manually every time, you can group them into a custom class.

In your CSS file (e.g., `styles.css`), you can use `@apply` to define the custom button class:

```css
.btn {
  @apply bg-blue-500 text-white py-2 px-4 rounded;
}
```

Then, in your HTML, you can simply use the `.btn` class:

```css
<button class="btn">Click Me</button>
```

This will apply the same Tailwind utility classes (`bg-blue-500`, `text-white`, `py-2`, `px-4`, and `rounded`) to the button element.

#### Example 2: Creating a Card Component

If you use cards throughout your site with the same structure, you can create a custom class for the card styles.

In your CSS:

```css
.card {
  @apply bg-white border rounded-lg shadow-lg p-6;
}
```

Then, use the `.card` class in your HTML:

```html
<div class="card">
  <h2 class="text-xl font-semibold">Card Title</h2>
  <p class="text-gray-600">Card content goes here.</p>
</div>
```

#### Example 3: Combining Utilities for Text Styling

You can also combine typography-related utilities into a custom class:

```css
.heading {
  @apply text-3xl font-bold text-gray-800;
}
```

Then, in your HTML:

```html
<h1 class="heading">Main Heading</h1>
```

This groups common text-related utilities into a single class.

### Benefits of Using `@apply` and Custom Classes

1. **Maintainability**: When the same styles are reused across multiple elements, grouping them with `@apply` reduces the need for repetitive utility classes in your HTML, making your markup cleaner and more maintainable.

2. **Consistency**: By creating custom utility classes, you ensure consistent styling across your project. Changes to the design can be made in one place (your custom CSS class) rather than across multiple HTML elements.

3. **Readability**: Long lists of utility classes can clutter your HTML. Custom classes allow for more semantic and readable HTML, which is easier for other developers to understand.

4. **Faster Development**: With custom classes, you can apply complex styles quickly by using a single class instead of writing out multiple utility classes every time. This improves development speed without losing the benefits of utility-first design.

### Limitations of `@apply`

While `@apply` is very powerful, there are a few things to keep in mind:
- You cannot use `@apply` with pseudo-classes (like `:hover` or `:focus`) in the same way as standard CSS selectors. Instead, you can use the regular CSS approach for pseudo-classes and combine them with Tailwind utilities.
- `@apply` works best for grouping Tailwind utilities, but it can’t replicate the full dynamic power of Tailwind (like variants or responsive classes).

### Conclusion

Using `@apply` to group often-used Tailwind CSS utilities into custom classes is a great way to keep your HTML clean,
maintainable, and consistent. By defining custom classes for repeated design patterns, you can speed up your development
process, reduce redundancy, and keep your codebase organized while still leveraging Tailwind’s powerful utility-first
design system.
